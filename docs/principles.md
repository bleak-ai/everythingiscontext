# gcontext

A folder standard that gives an AI agent a memory of your project.

## The problem

An agent forgets everything between sessions. You repeat the same
facts, it makes the same mistakes, and what it learned yesterday is
gone. The usual fix is one big notes file. It grows, nobody reads
it, and the agent stops finding things in it.

## The idea

Project knowledge lives in a folder called `context/`. The agent
writes every durable fact there. The tree is not designed up front.
It grows from the content, one rule at a time:

**A path is a chain of common denominators.** A folder name is what
all its entries share. A file holds everything about one subject.
Nothing else decides where a fact goes.

From that one rule follow three tests:

- A thing gets its own file when three facts are about it.
- Two files that share a name get a folder with that name.
- At every level, two entries always share something. When it is
  smaller than the folder they sit in, a folder is missing.

The result is a small tree of rich files. A newcomer, human or
agent, reads it top to bottom and knows how the project works.

## How it runs

Three moments, three tools.

1. **Save.** When the agent learns something durable, it saves the
   fact into the file of its subject. It creates a file or a folder
   only when the tests say so. Every index is regenerated by a
   script, never by hand.
2. **Track.** After every turn a status line shows how much the tree
   grew since the last structure check, in green, amber, or red.
3. **Check.** When the line is red, you run `/check-structure`. The
   agent proposes the smallest tree that passes the tests. You say
   apply, it moves the content, and the counter goes back to zero.

A git hook refuses a commit that breaks the structure.

## What it is not

- Not a database, not a vector store. Plain markdown in git.
- Not a config file the agent reads once. It writes there too.
- Not tied to one tool. The rules are one file. Any agent that can
  read and write files can follow them.

## Use it

```bash
uv tool install gcontext-ai
gcontext init
```

This writes `context/system/` (the rules and the scripts), the git
hook, and the two commands. Then work as usual and let the agent
save. Read `context/system/rules.md` once. It is the whole standard.
